# Insight Journal submission recipe (MyST + Pixi + MECA)

Distilled from `InsightSoftwareConsortium/InsightJournalTemplate` (branch `main`).
Re-verify upstream if significant time has passed — the template migrated off the
legacy LaTeX workflow (`InsightArticle.cls`, `IJ.tex`) and those tarballs/Overleaf
copies are **superseded**. The current artifact is a MyST Markdown + Pixi project
that submits a **MECA archive**, not a PDF upload.

## 1. Scaffold the official template

```bash
git clone https://github.com/InsightSoftwareConsortium/InsightJournalTemplate <paper-dir>
cd <paper-dir>
# Install Pixi if absent:
curl -fsSL https://pixi.sh/install.sh | bash
pixi run build        # builds manuscript AND tests bundled src/
```

Then replace the template's `myst.yml` and `docs/index.md` with the skill's
`assets/myst.yml` and `assets/index.md` starters and fill the placeholders
(title, ORCID, repo URL, IJ id).

## 2. Repository structure

```
docs/index.md        Main article (YAML frontmatter + MyST body)
docs/references.bib   Bibliography
docs/assets/          Figures (generated by committed scripts/, never hand-placed)
src/                  Accompanying C++ built against ITK (CMakeLists.txt + .cxx)
data/                 Input datasets / CSVs behind every quantitative claim
scripts/              Figure-generation + data-regeneration scripts (committed)
myst.yml              MyST project config (authors, exports, venue, licenses)
pixi.toml / pixi.lock Dependencies + task automation
```

## 3. Build / authoring tasks (`pixi run <task>`)

| Task | Description |
|------|-------------|
| `start` | Live preview server with hot reload |
| `build-pdf` | PDF via **Typst** — no LaTeX install required (default PDF path) |
| `build-html` | Interactive HTML |
| `build-docx` | Word export |
| `build-cff` | Generate `CITATION.cff` |
| `build-meca` | Build the **MECA submission archive** (`exports/article.meca.zip`) |
| `verify-meca` | Build MECA, unpack, rebuild — confirms a reviewer can reproduce |
| `build` | Main task: manuscript + test `src/` |
| `clean` | Remove build artifacts |

C++/ITK source (environment `cxx`): `pixi run -e cxx build-src` clones and
compiles ITK from source on first run (long initial build); `pixi run -e cxx test-src`
runs ctest. Manuscript-only tasks never touch ITK.

Without Pixi, the manuscript PDF also builds with the MyST + Typst CLIs directly:
`myst build --typst` (requires `myst` >= 1.10 and `typst`; `brew install typst`).

## 4. Submission flow (MECA, not a PDF upload)

1. Create the submission at <https://insight-journal.org>; it assigns an ID.
2. Put that ID in `myst.yml` → `project.id` (placeholder `insight-journal-000`).
3. `pixi run verify-meca` — **must reproduce cleanly before submitting**; open
   review re-runs the bundle.
4. `pixi run build-meca` → `exports/article.meca.zip`.
5. Upload the `.meca.zip` via the site (upload UI is behind login).

## 5. Journal principles reviewers enforce

- Open access, **open peer review** — reviewers re-run your bundle.
- **Reproducibility is mandatory:** ship source, input data, parameters, and
  expected output so results regenerate. State this in the abstract.
- **Licensing split:** Apache-2.0 for code, CC-BY-4.0 for article content
  (already encoded in `assets/myst.yml`).

## 6. Cross-reference gotchas (Typst PDF)

To get "Figure N" / "Table N" cross-references resolving in the Typst PDF:
- Use `myst` >= 1.10 (1.6 did not emit Typst labels reliably).
- Tables that need a cross-reference use the `{table}` directive wrapping a
  Markdown table with `:label:`. **Do not use `{list-table}`** — the
  `lapreprint-typst` template does not emit a Typst label for it.
- Figures use `{figure}` with `:label:`. Enable numbering in `myst.yml`.
