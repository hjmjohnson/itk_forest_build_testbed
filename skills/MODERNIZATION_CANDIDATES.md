# ITK modernization skills — mined from commit history

Generated by the `itk-modernization-skill-miner` workflow (mine → dedup → generate),
mining ~63.6k ITK commits (N-Dekker + hjmjohnson campaigns, clang-tidy, regex, and
general STYLE:/PERF: across all authors). 40 raw candidates → 14 new skills (deduped
against the 10 existing `itk-*` skills, 15 itk5to6 tasks, and the `cxx14_updates`
script trove).

Each skill lives in `skills/<name>/` with `SKILL.md` + a glob-safe `detect.sh`
(ThirdParty/ excluded), and — where safely automatable — a `transform.sh`
(dry-run by default, `--apply` to write, never commits). "review" skills are
medium-mechanizability: detection is the deliverable, transformation needs human
judgement. All `detect.sh` were run against the live ITK tree; match counts below
are in-ITK sites (downstream consumers have far more).

## Review guidance before mass-applying

- **High-volume auto-transforms** (`itk-auto-for-new` 1808, `itk-in-class-member-init`
  1349, `itk-prefer-prefix-increment` 1485): run `detect.sh` first, then
  `transform.sh` (dry-run) on a single module and build before applying broadly.
- **`itk-string-find-presence-test`** is a correctness fix (the legacy idiom is
  subtly wrong), not just style — prioritize it.
- **`review`-mode skills** intentionally ship detection only; their `SKILL.md`
  documents why automation is unsafe and what to check.
